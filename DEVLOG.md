# Spool DEVLOG

The release tracker records decisions, verification and open gates. The [protocol](protocol/README.md) describes the wire contract. The [readme](README.md) describes how to use the product.

## Milestones

- [x] **P0 — Prototype.** The SDK, portable runner API, SQLite state and stdio MCP passed local tests. Kin-generated JavaScript and Rust replay policy passed common cases.
- [x] **P1 — Live filesystem probes.** Real Docker and Cloudflare guests applied ordered tar and gzip layers. A fixed Cloudflare diagnostic executed a dynamically linked shell from a composed root and failed after its composed libc was removed. A separate kernel OverlayFS mount/read succeeded. Four Docker jobs ran across two real JetStream agents. Initial failures exposed Docker mount ownership, the Cloudflare guest-port scheme, and JetStream provisioning error handling. The implementations were corrected.
- [x] **P2 — Hosted verification.** The MIT repository contains the npm SDK, runner package, stdio MCP CLI, Rust crate, and release pipeline. The complete release bundle, including the Rust crate and OCI image, built locally. Public repository visibility restored hosted CI scheduling. GitHub Actions passed the Ubuntu and macOS suites, Rust checks, workerd, clean package installation, live Docker and Podman, and JetStream.
- [!] **P3 — Hosted reliability.** A native Cloudflare guest applied an R2-backed layer, ran for 16 minutes, emitted live heartbeats, accepted a deadline extension and returned its artifact. A deployment under Durable Object scheduling completed three consecutive cold starts. Each task read a cached layer, connected over loopback, failed to connect to an external TCP address and returned a SHA-256-verified 1 MiB artifact. Intermittent placement failures were observed under the default policy. Live R2 presigned PUT and multipart verification requires bucket-scoped S3 credentials.
- [ ] **P4 — Production full-root profile.** Implement the full-root adapter and test actual filesystem composition, containment, quotas, cleanup, and failure recovery. The fixed diagnostic is evidence of platform capability.

## Decisions

- **D001 — Portable HTTP, local MCP.** The runners implement the HTTP profile. Stdio MCP is a thin SDK consumer with access to the authoritative client cache.
- **D002 — Shared state without a resident process.** Separate stdio hosts can share a per-user cache through verified content-addressed files and atomic writes. Isolated mode creates a temporary directory. Custom mode uses the operator's path. Tasks stay durable at the runner.
- **D003 — Explicit release boundary.** The first distribution targets trusted workloads on self-hosted Docker. Cloudflare is a preview profile pending repeatable placement and an isolation review. Full-root execution remains a diagnostic result.
- **D004 — Reusable verification.** Pull requests and main run consumer, compatibility, runner and cross-language gates. Release builds use the same workflow and upload checksummed artifacts. An explicit dispatch input allows a prerelease draft to be staged from main.
- **D005 — Cache build inputs separately from archive bytes.** The local Taskfile cache verifies stored archives by SHA-256. A separate index keys archive builds by normalized inputs and ordered parents. Per-key SQLite transactions coordinate independent client processes and allow another builder to recover after an interrupted build.
- **D006 — Intentional wall-clock deadlines.** The submitter supplies the initial task timeout. An authenticated extension can move a running task's deadline up to the runner's fixed cap. In Cloudflare, alarms initiate the detached guest and perform short progress polls. The guest supervises the command independently and terminates on its hard deadline or loss of coordinator contact. The coordinator stores the guest log cursor.
- **D007 — Native guest and Babashka tooling.** The pinned Debian guest image ships one statically linked Rust executable. It verifies bounded archives, assembles the workspace, sets Linux resource limits, drops privileges, and collects results. Repository commands are available through `bb tasks`. JavaScript implements runner adapters, the Fetch SDK, and stdio MCP.
- **D008 — SSE and JSON observation.** Snug 0.2.0 supports bounded RFC 8742 sequences on JavaScript and Rust. On three simulated Spool event traces, CBOR reduced uncompressed size by 3–11% versus NDJSON. After gzip it saved 3% on line-sized logs and used slightly more bytes on batched logs and metadata. Spool uses text for logs and separate byte transfers for layers and artifacts. Use SSE for live compatibility and JSON for paging. Revisit CBOR when the event contract carries binary or higher-volume telemetry.
- **D009 — Storage-specific upload plans.** The manifest declares wire sizes before admission. The runner returns an authenticated gateway plan or scoped object-storage URLs plus a completion call. R2 and the optional self-hosted S3 backend keep signing credentials on the runner. The guest stages and verifies a byte stream from its runner cache. A 48 MiB live Docker probe verified disk-to-disk transfer and offline input availability. A TLS MinIO instance passed a presigned PUT and a 34 MiB multipart upload, both followed by Docker execution. The direct upload fixture covers destination allowlists and digest verification.
- **D010 — Cloudflare startup uses one deadline.** Failed and successful native smoke deployments used the same guest image digest. The late application health records showed healthy instances and no recorded errors. The guest now shares the coordinator's configured startup allowance across placement, readiness, and layer staging. Retries back off before command submission. The next live probe captured Cloudflare declining to allocate an instance to the Durable Object. Cloudflare did not identify which placement constraint or internal condition caused the refusal.
- **D011 — Serialize Cloudflare start attempts.** Cloudflare documents that start is asynchronous and the SDK retries allocation failures. A failed readiness probe stays with the current attempt. A retry starts only after a retryable startup error is reported, within the same deadline. Guest exits are surfaced separately. This fixes a possible overlap in Spool's prior loop. A hosted probe using the same scheduling policy passed R2-backed staging, live observation, deadline extension, and artifact retrieval. The cause of the earlier allocation refusals remains unconfirmed.
- **D012 — Platform entry points.** The runner package exports Node and Workers adapters. The consuming Worker application owns its authentication, Durable Object classes and bindings, and deployment configuration. The release bundles the container recipe and native guest source. Wrangler config is generated locally for verification. A disposable deployment using Durable Object scheduling pulled a named Spool guest image, staged a layer, ran the task and returned a verified 1 MiB artifact through R2.
- **D013 — Stream declared outputs.** The guest hashes selected regular files within an advertised per-task budget. Executors stream their contents into private runner storage, and the coordinator publishes downloads from a completed claim. The default budget is 256 MiB. The Docker transfer probe exercises a 48 MiB layer and a 1 MiB artifact. The Workers fixture exercises recovery and retrieval from R2-compatible storage in workerd.
- **D014 — Workspace layer leases.** A marker in each workspace identifies its layer references in the shared SQLite index. A layer can be collected after all references have expired or their markers have disappeared. JavaScript and Rust coordinate publication and collection through the same index. Taskfile builds and workspace-scoped MCP commands use leases automatically.
- **D015 — CLI authentication profiles.** A profile binds credentials to one runner origin. The CLI uses OAuth issuer discovery with device authorization or browser PKCE, or validates a manually provisioned bearer token. Profiles and refresh tokens stay in private state files outside the project MCP config.
- **D016 — MCP publication.** A version bump on main publishes `@3sln/spool-mcp` through npm trusted publishing and attaches six host-tested executables and the library tarballs to the GitHub release. `@3sln/spool-client` names the JavaScript library independently. Docker image packaging remains a local build option.
- **D017 — Runtime-neutral runner core.** The public `@3sln/spool-runner/core` entry point composes a Fetch handler, provider-backed state and storage, and the task lifecycle. Each state partition has one active coordinator, and competing workers use epoch-qualified claims and claim-scoped writes.
- **D018 — Independent build and execution resources.** Container-built Taskfile layers declare local CPU, memory, and scratch disk minima. The client selects a suitable Docker or Podman engine on a cache miss. The task manifest carries only the final command's runner requirements. Private output artifacts expire with task history and can seed a subsequent task's verified layer cache on the same runner.
- **D019 — Source mappings and byte patches.** Taskfiles map filtered source trees to explicit workspace destinations. The shared client compiler packs deterministic archives and tracks incremental VCDIFF chains in the leased cache. The guest verifies reconstruction before extracting the final archive. Live Docker and Cloudflare probes verified deletion, symlinks, sibling sources, and incremental uploads after the initial archive.
